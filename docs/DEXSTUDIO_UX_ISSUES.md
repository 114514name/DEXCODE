## 1. P0 —— 功能坏掉 / 点了没反应

### P0-1 「挂组件」按钮没有处理器 ✅ 已修
- 现象:唯一的组件挂载入口是死的(全仓库 47 处 `.onclick` 里没有它)。
- 修:`app.js` 接线 → `comp.add`;失败原因**同时**写输出面板 + 弹提示条;
  下拉带中文说明;成功后面板立刻出现该组件的字段。
- 验:页面自测**真的点一下**并断言 `entity.get` 里出现了 camera(`点「挂组件」真的挂上了组件`)。

### P0-2 「改名」按钮没有处理器 ✅ 已修
- 修:`app.js` 接线 + 回车提交;空名字拒绝;改名后**逻辑图里按名字的引用一起改**

- 验:`点「改名」真的改了名字`;`test_ui_contract` 断言改名后图里的 `obj` 同步。

### P0-3 `hidden` 属性被 CSS `display` 覆盖 → 4 个面板永远显示 ✅ 已修

- 验:页面自测把断言从"`.hidden` 属性"改成 **`getComputedStyle().display`**

- 附带:恢复提示条的措辞、按钮、收起逻辑一起复验。

## 4. 顺带修掉的真 bug(修复过程中自查发现的)

1. **删掉当前场景后回退到错误的路径**:`scene_list_rel()` 返回的是裸文件名
   (`main.json`),被当成"项目根下的 main.json"用,于是起始场景也变成了不存在的
   `main.json`(游戏跑起来是空场景)。改成一律返回 `scenes/x.json`。
2. **自测断言太弱漏掉整类问题**:页面自测过去只断言 `.hidden` 属性(68 项全过),
   现在断 computed display + **真的点按钮**。
3. **`btn-code-reload` 一度被我漏在 HTML 外**,导致 `Code.init()` 抛 TypeError、
   代码页签所有按钮都没接线 —— 现在有 `tools/check_web_ids.py` 专门挡这类问题。
4. **`entity.rename` 的错误分支**要求 `name` 非空却没给默认值;`res.rename` 现在
   只在真的改了引用时才标脏(以前改个文件名就触发"未保存"与自动保存)。

# B11 —— 用户报的四个"看不到效果" + Scratch 式积木模式

用户原话:「导入的预览图还是显示图片裂开的那个经典 Web 图片损坏图标,没有我导入的图片的
缩略图」「给物体改贴图了能看到物体的框线改变,但并没有实际的图像被显示」「声音预览也是
没有效果的」「现在这个代码块设计是认真的吗,这让零基础的用户怎么用…现在这个完全就是
把代码换了一种形式!必须修改」。

下面这条**最要命**,而且是这一轮才挖出来的:用户按「运行」其实**什么都没发生**。

| 症状 | 根因(实测) | 修法 | 守卫 |
|------|------------|------|------|
| 按「运行」什么都不发生 | IDE 生成的 `main.dex` 模板从不 `eng_init`,而 `eng_run` 的循环条件是 `while eng_running()` —— 没窗口它恒为 0,on_start 跑一遍就退出。**实测 60ms、exit 0、零输出** | 模板在 `eng_run` 前显式 `eng_init(dexstudio_game_title(), 960, 540, 1)`;`eng_run`/`eng_run_frames` 自己兜底自动开窗 | `test_template_game_really_runs`(编译 IDE 生成的那份 main.dex,2 秒后进程必须还活着) |
| 场景"加载成功",画面上却什么都没有 | 在 `eng_init` 之前加载场景时组件池还没建 → `dg_comp_kind()` 返回 -1 → 场景加载把 -1 当成"不认识的组件"**静默跳过**:实体在、名字在、`eng_find` 找得到,但 transform/sprite 一个都没挂上 | `dg_comp_kind()`/`dg_scene_parse()` 按需 `dg_scene_init()`;**"未知"与"还没准备好"必须能区分** | `test_scene_load_before_init` |
| 改了贴图**只有框线在动,图像没出现** | ① 框线公式与引擎画图不是同一个(`世界坐标 + 轴心` vs `世界坐标 - 源尺寸 × 轴心 × 缩放`);② `app.info` 报的视图是编辑器覆盖值,视口实际用的是活动相机;③ 旧模板留下的 `sprite.sw/sh = 32` 让大图只画左上角一角 | ① 宿主照抄引擎公式;② 没有覆盖时返回**实际生效**的相机视图;③ 换贴图时把"恰好 32×32"的裁切自动改成整张(带 `note` 说明),老项目打开时在内存里同样修正 | `test_outline_matches_pixels`、`test_viewport`、`test_sprite_scale` |
| 缩略图裂图标 / 声音试听没反应 | 这两条本来是 B9/B10 修过的,但**页面自测带项目跑的时候整段被 SKIP 了**(`DS.info` 还是 `refresh()` 之前的)→ 修好了也没人守着 | 自测自己记 `app.info`;新增 `test_page_with_project`:带 PNG+WAV 的临时项目跑页面自测,断言缩略图真的解码、声音真的能播 | `test_page_with_project`(skip 列表必须为空 + 那三条断言文本必须出现) |
| 「代码块」零基础没法用 | 节点图/代码页签对没写过代码的人是"换了一种形式的代码":要先理解事件、连线、字段 | 新增**积木**档:句子积木 + 全下拉,点一下就加,`如果…就` 有肚子,不连线不打字 | `test_blocks_model` / `test_blocks_behavior`(积木→代码→dexc→vm 真的动起来)、页面自测里"点一下左栏积木就加进去了"/"积木里的空是下拉"/"动作进了如果的肚子" |

# B12.4 —— 「导入图片一直显示图片读取失败,但点运行有图」

用户原话:「dexstudio项目的编辑器导入图片一直显示图片读取失败,给实例设置编辑器里也没有效果,
但点击运行实际是有图片的」。

**这次不是"资源加载坏了",而是"虚拟主机映射改了不算数"** —— 而且以前所有测试都恰好绕开了
用户真实的那条操作顺序。

| 症状 | 根因(实测) | 修法 | 守卫 |
|------|------------|------|------|
| 资源缩略图永远是"图片读取失败"(裂图标) | 缩略图靠虚拟主机 `dexstudio-proj.local` → 项目根 交给网页显示。**启动时没有项目**,映射是那时登记的;用户是**双击 exe 之后**再从界面打开项目 → 映射在页面加载完之后才设 → `SetVirtualHostNameToFolderMapping` 返回 S_OK,但**那个已经加载完的页面发出的请求照样失败**(`img` onerror / `fetch` 抛 `TypeError: Failed to fetch`)。只有**新的导航**才认新映射 | 宿主在映射改指向后自动重新导航一次:`sync_host_mappings()`(只在目标真的变了时动)→ `PostMessage(WM_APP_RELOAD)` → `ds_wv_reload()` → `location.reload()`。没有项目时先把两个主机名用预览目录**占位**登记,免得"从没登记过" | `test_page_open_late`(新增,走 `--open-late`:先加载页面再打开项目) |
| 给实例设了贴图,编辑器里没反应 | 同一条的两个表现:① 选中框/自动缩放那段靠浏览器 `new Image()` 读贴图尺寸,浏览器读不到图就**整段静默失效**;② 缩略图/资源面板本身也是裂的 | 自动缩放改成**问引擎**(`scene.outline` = 引擎按贴图算出来的世界包围盒 ÷ 当前缩放);浏览器那条只当兜底 | 页面自测原有的"换上贴图后选中框 = 整张贴图 × 缩放"(修前报 `贴图={"w":0,"h":0}`) |
| 点「运行」却一切正常 | 运行是引擎自己按项目根读文件,不经过 WebView2 的虚拟主机 —— 所以"有图"和"编辑器裂图"能同时成立 | —— | `test_template_game_really_runs`(原有) |
| 为什么以前 11 条资源断言全过还是漏了 | `--project <目录>` 是"导航前就映射好",一直是好的;`--wv-selftest`、`test_page_with_project`、发布形态自测**全都走这条路**,用户顺序一次都没被测 | 新增 `--open-late <目录>`(等 `ui.ready` 后调 `openProjectAt()`,就是双击 exe 的顺序);`dist/DexStudio` 重新打包并单独验一遍 | `test_page_open_late` 断言"资源检查真的跑了(不是当成没项目 SKIP)" |

**验收证据**

```bash
python tests/test_dexstudio.py                  # 490 项(新增 5 条:后开项目这条路)
dexstudio.exe --wv-selftest --open-late <项目>   # 页面自测 118 项、0 失败(修前 114 项 / 3 失败)
```

- 修前失败原文(三条,全在"后开项目"这条路):

  `换上贴图后选中框 = 整张贴图 × 缩放 … 贴图={"w":0,"h":0} k=1`。
- 用用户**自己的项目**(从 `%LOCALAPPDATA%\DexStudio\recent.json` 找到的
  `C:\Users\ASUS\Pictures\unprocessimg\我的游戏`,`res/猫_悲伤.png` 300×400)复现与验证,
  并且是拿它的**副本**在 ASCII 路径下跑,不动用户文件。

# B12.5 —— 「框线要适配图片大小、能拉能转」+ 拖动掉帧/图片比框线慢

用户原话:「目前这个逻辑不符合一般的编辑器的逻辑,我给示例套用图片之后,框线应该适配图片
大小,而不是原来的示例,我可以通过框线旋转拉伸图片,你懂那种设计思想吗,然后是严重的性能
问题,拖动编辑器框线时掉帧很严重,并且有图片的实例的贴图在移动框线时有延时,就是卡顿的
感觉,图片比框线运动的慢一点,不是和框线同步移动的」。

**一句话:编辑器把"引擎渲染的一张静态 BMP"当背景、框线由前端画 —— 于是"谁决定框线多大"
和"谁负责跟手"都得明确设计。**

| 症状 | 根因(实测) | 修法 | 守卫 |
|------|------------|------|------|
| 套了图之后框线还是"原来示例"的 32×32 | `scene.outline` 是**碰撞盒优先**(模板给玩家挂了 32×32 的 collider)→ 用户看到的是碰撞盒,不是图 | 改成**精灵优先**(精灵 > 碰撞体 > 瓦片地图);碰撞盒**单独给一份**,前端画青色虚线 | `test_sprite_transform`、"有碰撞盒时框线仍然围着图" |
| 换图之后尺寸总是不对 | 老模板留下的 `sprite.sw/sh = 32`(裁 32×32)在换图时只清裁切、不动缩放 → 大图铺满视口 / 只显示一角 | `comp.set sprite.tex_path` 里一并**按新图适配**:清掉"恰好 32×32"的旧裁切;用户**没手动缩放过**时按新图大小给合适缩放(长边 > 256 → 缩到 128);做了什么写进 `note` 弹给用户 | `test_sprite_scale` / `test_sprite_transform` |
| 不能通过框线旋转/拉伸 | `transform.rot` 从来是"只读、改了没效果"(引擎不读);框线也没有手柄 | 引擎:`dg_draw_quad_corners` + sprite **绕轴心旋转**(度,屏幕顺时针);宿主:框线四角用**同一公式**算好给前端;前端:8 个缩放手柄 + 1 个旋转手柄(Shift 等比 / 吸附 15°,拖完**一条撤销**) | `test_sprite_transform`(转 90° 时框线外接矩形 = 像素包围盒)、页面自测"手柄真的能拉能转" |
| 拖动时**掉帧严重** | 视口 `draw()` 直接挂在 `mousemove` 上:游戏鼠标一秒几百次事件,每次都重画整张预览图 + 网格线;`view.set` 也是每个事件发一条 | ① `requestDraw()` rAF 合帧;② "预览图 + 网格"进**离屏缓存**,视图没变就 blit;③ `view.set` 搭渲染那一拍发 | 页面自测:拖动过程里 **0 条命令**(`DS.cmds` 计数) |
| 图片比框线**慢半拍**(不同步) | 拖动时引擎那张 BMP 还是上一个位置的;而"每帧让引擎重渲染"更糟(D3D11 → BMP 落盘 1.9MB → `<img>` 解码,几十毫秒一帧) | 学一般编辑器:按下时让引擎**把被拖的精灵藏起来**(`sprite.visible` + `scene.render {hide}`,渲染完立刻还原、不动场景数据),画布上自己画一份**跟手**的贴图(仿射矩阵映射到四角,支持旋转/翻转/染色);松手才写一条撤销 | 页面自测:"拖动过程里不写模型""松手写回的就是预览那份""拖动时贴图真的画在画布上"、`test_sprite_transform` 的 hide/visible 契约 |

**验收证据**

```bash
python tests/test_dexstudio.py   # 508 项(新增 test_sprite_transform;页面自测 +6 条)
dexstudio.exe --wv-selftest      # 页面自测 97 项 / 0 失败(不带项目)
```

**顺带**(都是这条链路上暴露出来的):
- `sprite.visible` 成了正式字段(布尔,面板可勾):不看就藏,实体与逻辑照跑;
- `camera.rot` 仍是只读(引擎还没实现相机旋转),面板说明保持不变 —— 免得"没实现的字段"
  看起来能改;
- 前端不再自己用浏览器 `new Image()` 量贴图尺寸来做适配(那份逻辑搬到 C 了):浏览器读不到图
  (资源服务没连上 / 格式不认)时它以前会静默失效,表现就是"设了贴图编辑器里没反应"。
