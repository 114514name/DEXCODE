GAL 引擎与蓝图编辑器

用 DEXCODE 制作视觉小说 / GALgame:引擎是纯 C 的 libdexxgal.dll(渲染与交互), 场景用 UE 风格的蓝图节点编辑器(Python + tkinter)可视化设计, 一键导出 DexLang 代码、编译并运行。成品运行时无需 Python、无需任何第三方库。

纯 C 引擎 DLL UE 风格蓝图编辑器 打字机/选项/音频 菜单/存档点/跳转 主题/樱花/拖尾 编译内置 · 一键运行
简介 快速上手 编辑器界面 指令块 菜单编辑 运行与导出 引擎 API 主题与外观 存档点/跳转 场景文件 VM 与打包 常见问题

01GAL 引擎是什么?

GAL 引擎是 DEXCODE 的视觉小说引擎,由两部分组成:

  • 引擎:libs/gal/libdexxgal.dll 用纯 C + Win32 GDI 实现 (图片解码用单文件 stb_image.h,支持 PNG/JPEG/BMP 含透明通道;音频用系统 mci 播放 WAV/MP3),零第三方运行时依赖。
  • 编辑器:gal_main.py(Python + tkinter)启动的 蓝图节点编辑器——UE / Scratch 风格,拖块、连线、所见即所得预览, 导出 DexLang 代码后由 vm/galrun.exe 运行。

能力:背景图/纯色、角色立绘(4 图层,带透明)、打字机文本、点击推进、 选项分支、BGM 循环/音效、截图;文字位置(中间/左/右/偏左/偏右)、 对话框风格(有头像/人名/自适应)、立绘动画 (呼吸/淡入/上浮/抖动/脉冲/消失)、场景特效(滤镜)、菜单系统 (按钮/文字/图片/面板/输入框)、存档点/跳转、外观主题(含樱花)、 鼠标拖尾。

蓝图编辑器设计镜头/菜单→ 导出 DexLang 代码→ 内置编译 .dexbc→ galrun.exe 运行/发布

02快速上手

开发时启动编辑器(需 Python 3.10+,纯标准库,无第三方依赖):

python gal_main.py                 # 新建项目
python gal_main.py 作品.galscene   # 打开现有场景(发布版:gal_main.exe 双击即可)

打开后界面左侧是镜头 / 块 / 菜单 / 人物 / 项目 / 全局设置 六个页签, 中间是大画布(UE 蓝图式节点),右侧是属性面板。快速体验:

  1. 在左侧「块」页签点击 说话 添加到画布,右侧填入说话人与文本。
  2. 再点「镜头」页签设置背景图/纯色。
  3. 点工具栏 ▶ 运行:自动导出 → 内置编译 → 弹出 galrun.exe 游戏窗口。关闭窗口即结束,可继续编辑。

运行条件:需要 vm/galrun.exe 与 libs/gal/libdexxgal.dll 在编辑器目录下(发布版已随包附带;开发版就在项目根目录)。 编译已内置,无需配置 Python 解释器、无需命令行。

也可以跳过编辑器,直接用 DexLang 手写场景(见 examples/gal/demo_gal.dex):

include "gal";
func wait_click() {
    while gal_running() {
        gal_poll();
        if gal_text_done() && gal_clicked() { return; }
        gal_wait(16);
    }
}
gal_init(960, 540);
gal_set_title("星之语");
gal_bg_color(0x101018);
gal_speaker("小雨");
gal_text("早上好!今天也来得好早呢。");
wait_click();
gal_text_clear();
gal_close();

命令行编译运行(开发工具链):

python main.py compile examples/gal/demo_gal.dex
vm/vm.exe examples/gal/demo_gal.dexbc

资源路径:蓝图里填的图片/音频路径相对项目根目录; 示例资源在 examples/gal/res/。运行时代码里的路径相对 VM 进程的工作目录(即项目根)。

03编辑器界面

编辑器是 UE 风格的节点蓝图(参考 Scratch / UE Blueprint):

  • 顶部菜单/工具栏:新建 / 打开 / 保存 / 导出代码 / 完整资源导出 / 🧹 自动整理(一键重排当前画布节点)/ ▶ 运行 / ■ 停止。
  • 左侧六页签:
    • 镜头:项目镜头列表(一个镜头 = 一个舞台场景),＋/改名/－删。
    • 块:可滚动指令块面板,点击即添加到当前镜头, 或按住拖到画布指定位置。
    • 菜单:MENU 菜单场景管理(新建/编辑/删除/导入/导出),双击菜单名打开菜单编辑器。
    • 人物:人物集管理——每个人物含多张状态图(表情/姿态),立绘块直接引用"人物+状态"。
    • 项目:游戏标题、窗口尺寸、背景目录、项目根目录等。
    • 全局设置:新建块的默认属性(外观风格/文本/立绘/背景),单个块仍可单独覆盖。
  • 中央画布:节点从上到下沿白色 exec 连线顺序执行; 青色 value 连线传递数据(变量/运算/字面量)。滚轮缩放、拖节点移动、 拖引脚连线、右键菜单、Ctrl+Z 撤销 / Ctrl+Y 重做。
  • 右侧属性面板:选中块后编辑参数(文本、人物状态、动画、数值等)。

自动整理:节点多了乱成一团时点工具栏「🧹 自动整理」, 会把当前镜头所有节点按流程重排成整洁的列。

04指令块

数据输出点 / 场景数据把数据送出场景;引用其它场景的数据输出点。

05菜单编辑(MENU 场景)

在左侧「菜单」页签 ＋菜单 新建一个菜单,双击名字打开菜单编辑器。 菜单 = 一套可交互界面(主菜单/设置/存档页/输入框对话等),控件浮在游戏画面上。

节点说明
控件按钮 / 文字 / 图片 / 面板 / 输入框;设置位置、尺寸、 文字、图片与适配。
点击起点"当某控件被点击时…",连出后续逻辑。
信号起点"收到某信号时…"(与 gal_signal_emit 联动)。
退出结束菜单并返回结果(结果名可被镜头里的菜单块读取)。
数据入口镜头调用菜单时传入的参数(菜单块 → 菜单的输入)。
跳转镜头结束菜单并直接跳转到指定镜头。

菜单编辑器里也能用变量/运算/逻辑/字面量/文件/消息/等待/读输入框等数据块做逻辑。

输入框数据:菜单里的输入框控件会自动生成一个青色 数据输出口(名字=控件名),连出去即可把玩家输入传给变量;镜头侧用「读取输入框」块也能取。

菜单在镜头里通过 菜单 块运行(选菜单、模式:独占 modal / 叠加 overlay); 叠加菜单的退出节点自动生成输出口,可接后续流程。

06运行与导出

▶ 运行(开发预览)

工具栏「▶ 运行」:把整个项目导出为 scene_out.dex → 进程内编译 成 .dexbc → 用 vm/galrun.exe 打开独立游戏窗口。 关闭窗口即结束,可继续编辑;点「■ 停止」可强杀残留进程。

导出代码

「文件 → 导出代码」把当前项目导出一个 .dex 文件(单文件 DexLang),可手工查看/分发。

完整资源导出

「文件 → 完整资源导出」选一个输出目录,生成:

输出目录/
  scene_out.dex      # 代码
  res/               # 按项目目录结构复制的引用图片/音频
  scene_out.dexbc    # 可选:同时输出字节码(设置里开启)
  libdexxgal.dll     # portable 模式:引擎 DLL(文件夹自包含)

库链接模式(项目设置): static=引擎内嵌进字节码(单文件,换机免 DLL,默认); portable=文件夹自包含(带 DLL,相对路径引用)。

09存档点 / 跳转

用于做"读档页"式的自由跳转:流程经过存档点时自动记录当前位置; 之后跳转到存档点会读取该存档文件、恢复全部变量,并从存档点之后继续运行。

  • 存档点:放在剧情关键处(如每章开头),给一个唯一名字。 流程经过时记录位置(存档数据包) + 可选把变量写入文件。
  • 跳转到存档点:放在读档页/菜单按钮上,指定存档文件名; 执行时载入位置与数据,从存档点之后继续。

常见用法:主菜单 → 点击某存档 → 跳转到对应存档点,继续游戏。 存档点名在本镜头内唯一。

10场景文件格式(.bluescene)

编辑器保存的是 JSON(UTF-8,可手工编辑),扩展名 .bluescene; 结构为项目 → 人物集 → 镜头列表 → 节点图(节点 + 连线)。核心字段:

{
  "format": "bluescene",
  "title": "星之语 · 蓝图示例",      // 游戏标题
  "win_w": 960, "win_h": 540,       // 窗口尺寸
  "chars": [                        // 人物集
    { "name": "小羽",
      "states": ["res/xy_smile.png", "res/xy_angry.png", ...],
      "stateNames": ["微笑", "生气", ...] }
  ],
  "scenes": [                       // 镜头列表
    { "title": "清晨的海",           // 镜头标题
      "bg": "res/bg_day.png",       // 背景图(相对项目根)
      "bgColor": 1052696, "useBgImg": 1,
      "nodes": [ ... ],             // 节点图(入口/说话/立绘/选项…)
      "links": [ ... ]              // exec/value 连线
    }
  ],
  "menus": [ ... ]                  // MENU 菜单场景
}

一般无需手写 JSON——直接在编辑器里可视化编辑即可;了解结构方便备份/排查/版本管理。 .menubluescene 是单个菜单的独立文件,用于菜单的导入/导出。

11VM 版本与发布打包

文件用途行为
vm/vm.exe开发/调试带控制台,vm <file.dexbc>
vm/vmnc.exe无控制台运行隐藏控制台窗口(FreeConsole)
vm/galrun.exe发布版 VM无控制台 + 无参数时自动读取同目录 core.do

三者共享同一份 vm/vm.c;发布版/无控制台版通过 -DPUBLISH_BUILD 宏启用 FreeConsole(),并支持"无参数读 core.do"。

一键发布成品

python main.py release examples/gal/demo_gal.dex \
    -o release --res examples/gal/res --title "星之语"

生成的结构:

release/
  galrun.exe        # 发布版 VM(无控制台,自动读 core.do)
  core.do           # 游戏字节码
  res/              # 图片/音频资源
  启动游戏.bat      # 双击开玩
  游戏说明.txt

分发:整个 release/ 目录拷给玩家即可。运行时只需 galrun.exe + core.do + res/,无需 Python、无需任何 DLL。 (若用 portable 链接模式,还需 libdexxgal.dll。)

12常见问题

编辑器/游戏乱码?

引擎与 VM 都以 UTF-8 输出;请确保 .bluescene 与 .dex 用 UTF-8 保存。 控制台窗口出现中文乱码时,Windows 终端需开启 UTF-8 或使用 galrun.exe(无控制台)。

点「▶ 运行」提示找不到 VM?

需 vm/galrun.exe 在项目根/编辑器旁;在「项目设置」里把 VM 位置指到 vm/galrun.exe 或 vm/vm.exe。

图片没显示 / 路径不对?

蓝图里的资源路径相对项目根目录(如 res/bg.png);请确认文件确实 在该相对位置,且项目根目录正确。

需要装 Python / 第三方库吗?

开发版需要 Python 3.10+(纯标准库 tkinter,无第三方依赖);发布版已用 nuitka 打包成独立 exe,双击即用,无需 Python。成品(玩家侧)只需要 galrun.exe + 字节码 + 资源。
