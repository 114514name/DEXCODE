01简介

在 Windows 上,图形界面的底层是 Win32 API(用户态接口,位于 user32.dll、 kernel32.dll 等系统 DLL)。任何"窗口程序"——记事本、浏览器,乃至本项目的 DEXIDE——最终 都是通过这些 API 跟系统交互的。

本项目的 UI 库(libs/ui/libdexui.dll)是一个纯 C 编写的小封装: 用 WinAPI 创建窗口和控件(标签/按钮/输入框),再把这 10 个底层动作暴露成 DexLang 能调用的函数。 它完全由 C 实现、零依赖、零 Python。

DexLang 程序→ include "ui" + NCALL→ libdexui.dll(纯 C)→ Win32 API(user32.dll)→ 🪟 窗口

02WinAPI 核心概念

写一个 Win32 窗口程序,通常走五步(本项目 DLL 里正是这么做的):

步骤API作用
1. 定义窗口类RegisterClassW(WNDCLASS)登记"这种窗口长什么样、事件交给谁处理"
2. 创建窗口CreateWindowExW按类实例化一个窗口,返回句柄 HWND
3. 创建控件CreateWindowExW(BUTTON/STATIC/EDIT)在窗口里放按钮/标签/输入框(控件也是窗口!)
4. 消息循环GetMessage/PeekMessage + DispatchMessage不断取消息、派发给窗口过程
5. 处理事件WndProc(窗口过程)收到 WM_COMMAND 等消息后做出响应

核心思想:窗口是被"消息"驱动的——用户点鼠标、敲键盘,系统都会生成一条消息, 放进程序的消息队列;程序循环取消息,派发到对应窗口的窗口过程去处理。

03句柄(HANDLE)与控件

Windows 不喜欢把内部对象直接交给你,而是给一个句柄(一个整数"编号"), 你通过它请系统办事。窗口是 HWND,按钮/标签/输入框也各有自己的 HWND—— 控件本质上是"子窗口"。

HWND win  = CreateWindowExW(...);              // 主窗口句柄
HWND btn  = CreateWindowExW(L"BUTTON", ...,    // 按钮(子窗口)
                            win, (HMENU)(INT_PTR)3, ...);
// 给控件一个"数字 id"(这里的 3)非常重要:
// 点击按钮时,WM_COMMAND 消息会带上这个 id(GetDlgCtrlID),
// 程序靠它区分"是哪个按钮被点了"。
本项目的教训:最初 dex_ui_button 创建按钮时没把控件 id 传给 HMENU,导致 GetDlgCtrlID 恒为 0,点击事件永远对不上——表现为"点按钮没反应"。 修复:把分配的 id 作为 (HMENU)(INT_PTR)id 传入即可。

04消息(Message)与事件模型

最常见的消息之一:WM_COMMAND——控件被激活(按钮点击、菜单选择)时发给父窗口。

// 窗口过程:所有消息都进这里
LRESULT CALLBACK WndProc(HWND h, UINT msg, WPARAM w, LPARAM l) {
    switch (msg) {
    case WM_COMMAND:
        // 按钮点击:HIWORD(w) == BN_CLICKED;LOWORD(w) == 被点按钮的 id
        if (HIWORD(w) == BN_CLICKED) clicked_id = LOWORD(w);
        return 0;
    case WM_DESTROY:      // 窗口被关闭
        running = 0;
        return 0;
    }
    return DefWindowProcW(h, msg, w, l);   // 其余交给系统默认处理
}

消息循环有两种口味,本项目两种都用:

方式API特点
阻塞式GetMessage没有消息就睡着(省 CPU);窗口关闭才返回
轮询式PeekMessage有消息就处理,没有立刻返回(适合"边跑逻辑边管窗口")

本项目把这两种包装成:dex_ui_run(win)(阻塞式,纯显示)与 dex_ui_poll(win)(轮询式,配合事件返回,做交互)。

又一个教训:窗口关闭时若调用 PostQuitMessage,会把 WM_QUIT 塞进消息队列,污染同一线程里"下一个窗口"的轮询(表现为 poll 莫名返回 -1)。 所以这里让 WM_DESTROY 只置 running=0,不投递 WM_QUIT。

05libdexui 库设计:从 WinAPI 到 DexLang

WinAPI 函数参数很多,但 DexLang 的 FFI 限制每个函数最多 3 个参数。怎么把 CreateWindowExW(类, 标题, 样式, x, y, 宽, 高, 父窗, id, 实例, 参数) 塞进去?

设计取舍:

  • 位置只给 y(控件沿纵向排布,横坐标/宽度由库自动计算)
  • 文本用 dex_ui_set_text(control, text) 事后设置(创建时不传)
  • 窗口 id、控件 id 都是库内部递增分配的整数,作为"句柄"返回给 DexLang
  • 中文全链路:UTF-8(DexLang)↔ UTF-16(WinAPI)用 MultiByteToWideChar/WideCharToMultiByte 互转
// 库内部:一次注册一个窗口类,记录句柄与控件表
typedef struct { HWND hwnd; int id; } Ctrl;
typedef struct {
    HWND hwnd; int running;
    Ctrl ctrls[MAX_CTRL]; int nctrls; int next_ctrl_id;
} Win;

EXPORT int64_t dex_ui_button(int64_t win, int64_t y) {
    Win *wn = get_win(win);
    int cw = client_w(wn->hwnd);              // 窗口客户区宽度
    int cid = wn->next_ctrl_id++;             // 分配控件 id
    HWND h = CreateWindowExW(0, L"BUTTON", L"",
                             WS_CHILD | WS_VISIBLE | BS_PUSHBUTTON,
                             cw - 118, (int)y, 104, 24,
                             wn->hwnd, (HMENU)(INT_PTR)cid,  // ← id 必须传!
                             GetModuleHandleW(NULL), NULL);
    wn->ctrls[wn->nctrls].hwnd = h; wn->ctrls[wn->nctrls].id = cid;
    wn->nctrls++;
    return cid;                                // 返回控件 id 给 DexLang
}

控件 id 同时被三处使用:返回给 DexLang 程序、作为 HMENU 让 GetDlgCtrlID 返回它、在 WM_COMMAND 里出现。三者一致,事件才能对上。

06API 详解(10 个函数)

接口定义在 libs/ui/ui.dexdef。每个签名都落在 C VM 的 FFI 支持集合内。

函数签名说明
dex_ui_create(title: string, w: int, h: int) -> int创建主窗口,返回窗口 id
dex_ui_label(win: int, y: int) -> int添加标签,返回控件 id
dex_ui_button(win: int, y: int) -> int添加按钮(点击产生事件)
dex_ui_edit(win: int, y: int) -> int添加输入框
dex_ui_set_text(control: int, text: string) -> int设置控件文本
dex_ui_get_text(control: int) -> string读取控件文本(支持中文)
dex_ui_running(win: int) -> int窗口是否还开着(1/0)
dex_ui_poll(win: int) -> int泵消息并返回事件(见下)
dex_ui_run(win: int) -> int阻塞运行到窗口关闭(纯显示)
dex_ui_destroy(win: int) -> int销毁窗口

事件约定(dex_ui_poll 的返回值):

  • 0 —— 没有事件
  • > 0 —— 被点击的按钮控件 id
  • -1 —— 窗口已关闭

07示例程序

这就是 examples/ui/demo_ui.dex —— 输入名字,点按钮,标签显示问候语:

include "ui";

let win = dex_ui_create("DEX UI 示例", 340, 170);
let lbl = dex_ui_label(win, 12);
let ed  = dex_ui_edit(win, 44);
let btn = dex_ui_button(win, 80);
dex_ui_set_text(lbl, "输入名字,然后点按钮");
dex_ui_set_text(btn, "打招呼");

// 交互模式:轮询消息 + 处理事件
while dex_ui_running(win) {
    let e = dex_ui_poll(win);                 // 泵消息,返回事件
    if e == btn {                             // 是"打招呼"被点
        dex_ui_set_text(lbl, "你好, " + dex_ui_get_text(ed) + "!");
    }
}
print "窗口已关闭";

逐行对照 WinAPI 概念:

DexLang 代码背后做的 WinAPI 事
dex_ui_create(...)RegisterClassW + CreateWindowExW + ShowWindow
dex_ui_label / edit / buttonCreateWindowExW(STATIC / EDIT / BUTTON 子窗口)
dex_ui_poll(win)PeekMessage + DispatchMessage(把点击派发给窗口过程)
e == btn窗口过程在 WM_COMMAND 里记下被点按钮的控件 id
dex_ui_set_text(...)SetWindowTextW
dex_ui_get_text(...)GetWindowTextW + UTF-16→UTF-8
while dex_ui_running(win)WM_DESTROY 把 running 置 0,循环退出

08构建与运行

UI 库 DLL 需要 user32.dll 等系统库,用 zig 的 MinGW 目标编译:

zig cc -shared -target x86_64-windows-gnu -O2 \
    -o libs/ui/libdexui.dll libs/ui/libdexui.c
# 编译 + 运行(会出现窗口)
python main.py compile examples/ui/demo_ui.dex
python main.py run examples/ui/demo_ui.dexbc
# 或在 DEXIDE 里打开 examples/ui/demo_ui.dex,点「▶ 运行」/「终端」

静态内嵌版:把 ui.dexdef 换成 ui_static.dexdef(refer static), DLL 字节会打包进 .dexbc,分发时无需外部 DLL。

09常见问题

Q1:窗口一闪而过?/ 程序立即结束?

消息循环没跑起来。要么用 dex_ui_run(win)(阻塞),要么用 while dex_ui_running(win) { let e = dex_ui_poll(win); ... }(轮询)。

Q2:点按钮没反应?

控件 id 没对上(见 03 节教训):创建控件时必须把分配的 id 传给 HMENU, 否则 WM_COMMAND 里 LOWORD(w) 是 0,永远不等于按钮 id。

Q3:关闭窗口后,再开一个窗口,poll 总是返回 -1?

上一条 WM_QUIT 残留(见 04 节教训)。保证 WM_DESTROY 只置 running=0、不 PostQuitMessage 即可。

Q4:中文乱码?

WinAPI 用 UTF-16,本库在 DLL 内部用 MultiByteToWideChar / WideCharToMultiByte 与 DexLang 的 UTF-8 互转,全链路保持中文不乱码。

Q5:能否自定义窗口内容?

这是"教学级"库,目前固定三种控件(标签/按钮/输入框)和一种纵向布局。 想扩展可在 libs/ui/libdexui.c 里仿照 dex_ui_button 增加新控件与布局。
